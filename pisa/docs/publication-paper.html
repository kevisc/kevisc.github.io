Educational Inequality Data Explorer: A Web-Based Methodological Article on ESCS-Based Stratification in PISA Outcomes

Author: Kevin Schoenholzer

Correspondence: kevinschoenholzer.com

Date: 2026-01-04

Abstract. This article introduces the Educational Inequality Data Explorer, a browser-based analytical application for OECD PISA microdata. The tool is specifically geared to understanding how the ESCS index—capturing parental wealth, occupation, and education—relates to student achievement across countries and PISA cycles. It operationalizes standard inequality metrics, survey-weighted regression models, and variance decomposition techniques in a transparent and reproducible workflow. It is designed to lower barriers for non-specialist researchers, students, and graduate students who need rigorous comparative analysis without writing bespoke statistical code. The application makes it straightforward to test how results change with alternative estimators, weighting choices, and country selections, thereby supporting open science, sensitivity analysis, and replicability. We document all methodological choices, model specifications, weighting conventions, and data-handling procedures, and we provide direct links to technical appendices for audit and replication.

Keywords: educational inequality, ESCS, PISA, survey weighting, regression, variance decomposition, web-based analytics, reproducibility

1. Introduction

Large-scale assessment data provide an unparalleled opportunity to study educational inequality within and across countries. However, the technical barrier to entry remains high due to complex survey designs, the need for transparent weighting conventions, and the burden of repeated, customized analysis for different outcomes and sample definitions. The Educational Inequality Data Explorer addresses this gap by providing a validated, browser-based analytical environment that adheres to OECD documentation standards while prioritizing interpretability and reproducibility.

This article positions the application as a methodological contribution that democratizes access to comparative analysis. It enables users with limited statistical programming background to explore how the ESCS index (parental wealth, occupation, and education) relates to student outcomes, and how estimation choices (OLS vs. fixed or random effects), weighting decisions, and country or year selections influence substantive conclusions. The accompanying exports and documentation are designed to make analytic decisions explicit, supporting open science and replicability.

1.1 Contribution and Audience

The application is intended for researchers, instructors, and students who need rigorous comparative analysis without bespoke statistical code. Its contribution is both methodological and infrastructural:

  • Accessibility: non-specialist users can reproduce core inequality metrics and regression models directly in the browser.
  • Comparative sensitivity: users can systematically compare estimators and country selections to assess how methodological choices shape conclusions.
  • Open science: every analysis is exportable with metadata that preserves the analytic context, supporting transparent reporting and replication.

2. Data and Coverage

The application uses student-level microdata from the OECD PISA program. The current deployment includes all cycles from 2000 to 2022 (eight assessment waves), enabling comparisons across countries and over time. Data are accessed through the learningtower R package, which harmonizes variable naming conventions and coding across cycles.

2.1 Sample Construction

Data are stored in country-year JSON chunks. When users select a set of countries and years, only the corresponding subsets are loaded, reducing memory use and preserving interactivity. Students are retained if they have finite values for the selected outcome and predictor variables, as well as any selected controls. Records with missing values in required fields are excluded via listwise deletion to preserve consistent sample definitions across models.

2.2 Key Variables

The primary outcome variables are PISA achievement scores in mathematics, reading, and science. The primary stratification variable is ESCS (Economic, Social, and Cultural Status). Parental education and gender are supported as optional control variables. The application uses the first plausible value for each achievement domain for tractability; this choice is documented as a limitation and can be extended to multiple plausible values in future releases.

The learningtower package includes a large and diverse set of student, family, and school variables, enabling flexible model specification beyond the core variables emphasized in the interface.

3. Statistical Methods

All analyses conform to standard definitions used in educational inequality research. The application exposes these methods through modular tabs that compute summary statistics, inequality measures, regression models, and diagnostic checks.

3.1 Survey Weighting

By default, all descriptive and regression statistics use the student sampling weight (W_FSTUWT). Users may optionally select the senate weight (W_FSENWT) for alternative estimands. Results are computed as weighted quantities, with safeguards against non-positive or non-finite weights.

Weighted mean: mu = sum(w_i * y_i) / sum(w_i) Weighted variance: var = sum(w_i * (y_i - mu)^2) / sum(w_i)

3.2 Inequality Metrics

Within-sample inequality is summarized using the Gini coefficient, coefficient of variation, and percentile ratios. These measures are calculated on achievement scores using weighted estimates where appropriate. The Lorenz curve is plotted to contextualize Gini values.

3.3 SES Gradient

The SES gradient is computed as the slope of a weighted bivariate regression of achievement on ESCS. This coefficient is interpreted as the change in achievement (score points) associated with a one-unit increase in the ESCS index.

3.4 Achievement Gap Decomposition

The application calculates Q4-Q1 gaps by constructing SES quartiles using weighted ranks. It reports mean differences, pooled standard deviations, and Cohen's d for effect size interpretation.

3.5 Regression Models

Three model families are implemented:

  • Pooled OLS: Baseline weighted regression ignoring country clustering.
  • Fixed Effects: Country fixed effects (and optional year fixed effects) controlling for time-invariant country heterogeneity.
  • Random Effects: Country-level random intercepts with quasi-demeaning transformation.
Pooled OLS: y_i = beta_0 + beta_1 x_i + gamma' c_i + e_i Fixed Effects: y_it = alpha_i + beta_1 x_it + gamma' c_it + e_it Random Effects: y_it = beta_0 + beta_1 x_it + gamma' c_it + u_i + e_it

Estimation uses weighted least squares with positive survey weights, ridge stabilization for near-singular designs, and conventional (model-based) standard errors. Fit statistics include R-squared, adjusted R-squared, AIC, and BIC. Confidence intervals are reported as coefficient plus or minus 1.96 standard errors.

Model diagnostics include residual plots, Q-Q plots, and Hausman tests when both FE and RE models are available. A small ridge term stabilizes near-singular designs arising from many fixed effects.

3.6 Variance Decomposition

Variance is partitioned into within- and between-country components using one-way ANOVA. The intraclass correlation coefficient (ICC) reports the proportion of variance attributable to country-level clustering.

4. Implementation Architecture

The application is implemented as a modular ES6 JavaScript codebase and a set of R scripts that generate data chunks and metadata. The pipeline produces a metadata catalog listing countries, years, and variables, which drives the user interface and data loading flow. All statistical computations are performed in the browser, preserving user control and data privacy once the files are loaded locally.

5. Validation and Quality Assurance

Data integrity is verified via automated validation scripts that check for missing files, inconsistent record counts, and malformed JSON. Model outputs are bounded and checked for non-finite values to prevent erroneous reporting. Diagnostic plots are sampled to limit performance bottlenecks while preserving distributional structure.

Reproducibility note: The application exports all intermediate outputs (CSV tables, PNG/SVG figures, and HTML reports). These exports encode the selected countries, years, outcome variables, predictor variables, control choices, and weighting schemes at the time of analysis.

6. Interpretation and Use Cases

The tool is designed for academic briefs, policy reports, and exploratory research. Users can benchmark achievement gaps across countries, compare model specifications, or evaluate how SES gradients evolve across cycles. All results should be interpreted as descriptive associations rather than causal effects.

7. Limitations

  • Only the first plausible value is used in the current implementation.
  • Replicate weights are not yet implemented; inference should be treated as approximate.
  • Listwise deletion may bias results if missingness is not random.
  • Cross-sectional PISA data do not support causal inference.

8. Availability and Citation

The application and data pipeline are open source and available through the project repository. The documentation is structured to enable transparent replication and reuse, with all analytic choices surfaced in the UI and export metadata. Citation guidance is provided in the linked documentation.
